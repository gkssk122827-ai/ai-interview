# AI Interview Platform 발표 자료 정리

## 1. 프로젝트 한 줄 소개

- AI 기반 모의면접과 학습 데이터를 결합해, 면접 연습부터 복습, 약점 분석, 학습 추천까지 연결하는 통합 취업 준비 플랫폼

## 2. 프로젝트 목표

- 사용자가 이력서, 자기소개서, 채용공고를 기반으로 실제 지원 맥락에 가까운 모의면접을 진행할 수 있도록 한다.
- 면접 결과를 점수와 피드백으로만 끝내지 않고, 학습 현황, 오답노트, 성취 시스템과 연결해 반복 학습 구조를 만든다.
- 단순 면접 서비스가 아니라 면접 준비와 학습 루프를 하나의 서비스 안에서 완성하는 것을 목표로 한다.

## 3. 해결하려는 문제

- 기존 면접 준비는 자료 관리, 예상 질문 정리, 답변 연습, 복습이 각각 분리되어 있어 학습 흐름이 끊기기 쉽다.
- 사용자는 자신의 이력과 지원 공고에 맞는 맞춤형 질문을 받기 어렵고, 피드백도 정량화되기 어렵다.
- 면접 결과를 실제 학습 개선으로 연결하는 기능이 부족하다.

## 4. 핵심 가치 제안

- 개인 문서 기반 맞춤 면접: 이력서, 자기소개서, 채용공고를 바탕으로 질문 생성
- AI 피드백 자동화: 답변별 분석과 종합 리포트 제공
- 학습 루프 연결: 학습 세션, 오답노트, 성취 시스템, 통계 대시보드 연동
- 서비스 확장성 확보: 백엔드와 AI 서버를 분리해 역할을 나눈 구조

## 6. 시스템 구성

- 프론트엔드는 사용자 UI와 상태 관리를 담당한다.
- Spring Boot 백엔드는 인증, 비즈니스 로직, 데이터 저장, 통계/리포트 집계를 담당한다.
- FastAPI 기반 AI 서버는 질문 생성, 답변 분석, 리포트 요약, 음성 처리 같은 AI 전용 기능을 담당한다.
- 배포는 프론트엔드와 백엔드, AI 서버를 분리해 각각 CI/CD 파이프라인으로 운영한다.

### 구조적 장점

- AI 관련 책임을 별도 서버로 분리해 백엔드 비즈니스 로직과 관심사를 나눌 수 있다.
- 프론트, 백엔드, AI 서버가 느슨하게 연결되어 추후 모델 교체나 기능 확장이 상대적으로 쉽다.
- 모놀리식 한계 없이 서비스 성격에 맞는 기술을 혼합해 사용할 수 있다.

## 8. 발표에서 강조할 수 있는 장점

### 장점 1. 단일 기능이 아니라 준비-실전-복습까지 이어지는 서비스

- 많은 프로젝트가 AI 질문 생성이나 챗봇에 머무르지만, 이 프로젝트는 면접 실행 이후 학습 데이터까지 연결한다.
- 사용자는 면접 한 번으로 끝나는 것이 아니라, 결과를 기반으로 다시 학습하고 성취를 누적할 수 있다.

### 장점 2. 사용자 맥락 기반 개인화

- 이력서, 자기소개서, 채용공고를 함께 활용해 일반적인 면접 질문이 아닌 지원 맥락에 맞춘 질문을 만들 수 있다.
- 실제 취업 준비 상황과 더 가까운 경험을 제공한다.

### 장점 3. 백엔드와 AI 서버의 분리

- 일반 비즈니스 로직은 Spring Boot에서 처리하고, AI 생성/분석은 FastAPI 서버로 분리했다.
- 역할이 분리되어 유지보수와 확장성이 좋고, 모델 교체나 AI 기능 추가에 유리하다.

### 장점 4. 데이터 기반 대시보드와 성취 시스템

- 단순 결과 조회가 아니라 평균 점수, 최고 점수, 연속 학습, 총 학습량 같은 데이터를 집계한다.
- 서비스 체류와 반복 사용을 유도하는 구조를 갖고 있다.

### 장점 5. 운영까지 고려한 프로젝트

- GitHub Actions 기반 CI/CD
- 프론트/백엔드/AI 서버 분리 배포
- AWS 인프라 사용
- 테스트 코드와 예외 처리 구조 보유

## 9. 기술적으로 잘 설계된 포인트

### 1) 표준 API 응답 형식

- 성공/실패를 공통 포맷으로 감싸 프론트와 백엔드 계약을 단순화했다.
- 예외 상황에서도 일관된 형태로 응답할 수 있다.

### 2) 글로벌 예외 처리

- Validation 에러, 바인딩 에러, 권한 에러, 서버 에러를 중앙에서 처리한다.
- 프론트 입장에서는 에러 메시지 소비 방식이 단순해진다.

### 3) 기능 중심 패키지 구조

- `user`, `profile`, `interview`, `learning`, `subscription`, `order`, `admin` 등 도메인 기준으로 분리되어 있다.
- 기능 확장 시 영향 범위를 예측하기 쉽다.

### 4) 통계 집계와 상태 구분

- 면접 세션 상태를 `IN_PROGRESS`, `COMPLETED`로 분리한다.
- 완료된 면접만 통계에 반영하도록 집계 로직을 분리해 데이터 왜곡을 줄일 수 있다.

### 5) 프론트 상태 관리 최소화 전략

- 복잡한 전역 상태는 Zustand로 분리하고, 나머지는 페이지 단에서 관리한다.
- 작은 규모 프로젝트에서 과한 상태관리 복잡도를 피할 수 있다.

## 10. 발표용 차별화 포인트

- AI 면접 + 학습 플랫폼을 하나의 서비스로 통합했다.
- 취업 준비에 필요한 문서, 질문, 답변, 피드백, 복습 흐름이 연결되어 있다.
- 면접 결과를 통계와 성취 시스템으로 이어지게 설계했다.
- 단순 프로토타입이 아니라 인증, 결제, 관리자, 배포까지 포함한 서비스형 프로젝트다.

## 11. 트러블슈팅 소재로 쓰기 좋은 내용

### 1) 미완료 면접 점수가 통계에 섞이던 문제

- 원인: 미완료 세션에서 임시 점수 또는 null 점수가 0처럼 해석되면 평균이 왜곡될 수 있음
- 해결: 통계 집계 시 `COMPLETED` 상태만 필터링해서 평균, 최고 점수, 추세를 계산
- 발표 포인트: "데이터 상태와 사용자 상태를 분리하지 않으면 통계가 쉽게 왜곡된다"

### 2) 인증 상태 복구 문제

- 원인: 브라우저 새로고침이나 만료 토큰 상황에서 보호 페이지 접근 시 UX가 깨질 수 있음
- 해결: Axios 인터셉터와 refresh 흐름으로 토큰 재발급 처리
- 발표 포인트: "기능 구현보다 세션 유지 경험이 실제 서비스 완성도에 더 직접적이다"

### 3) AI 기능과 일반 비즈니스 로직의 결합 문제

- 원인: 모든 기능을 한 서버에 넣으면 배포와 장애 대응이 어려워질 수 있음
- 해결: AI 서버 분리로 책임을 나누고 API 기반으로 연결
- 발표 포인트: "AI 기능은 빠르게 바뀌므로 독립적인 서비스 경계가 중요하다"

## 12. 협업 및 운영 관점에서의 강점

- CI에서 프론트 빌드와 백엔드 테스트를 자동 실행한다.
- 프론트, 백엔드, AI 서버를 각각 독립 배포한다.
- AWS S3 + CloudFront로 정적 프론트를 배포하고, 백엔드/AI 서버는 ECR 이미지 기반으로 EC2에서 운영한다.
- 테스트 코드가 존재해 핵심 흐름 검증 기반이 있다.

## 13. 아쉬운 점과 개선 방향

- 일부 화면은 아직 서버 API와 100% 완전히 연결되지 않은 부분이 있다.
- README와 환경 변수 문서가 더 정리되면 협업과 온보딩이 쉬워진다.
- AI 답변 품질 평가 기준을 더 정교하게 만들면 서비스 신뢰도를 높일 수 있다.
- 사용자 행동 데이터 기반 추천까지 확장하면 플랫폼 성격이 더 강해질 수 있다.
